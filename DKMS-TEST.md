# Эксперимент: DKMS для нашего CMP 90HX установщика

Ветка `experimental/dkms` сохраняет compute + GEN2CHAIN из Rhonstin и нашу
интеграцию: BAR0/SS-проверки, prime, fast/full службы, fallback и
`nvidia-pstated`. Меняется способ сборки и установки kernel modules.
Это не порт на Zagitta и не переход на другую версию NVIDIA.

Поддерживаемые профили прежние: CachyOS LTS 6.18 и Debian 13 / 6.12,
x86_64, одна CMP 90HX, Secure Boot выключен. Пользовательская часть
NVIDIA остаётся 610.43.03. Экспериментальный DKMS build разрешён только
для ядер 6.12 и 6.18, в том числе при `--allow-unsupported-host`.

## Миграция уже работающей установки

Используйте `unlock_cmp90hx.sh` из этой ветки в том же каталоге, где лежит
сохранённый `cmp90hx-work`, либо укажите прежний `CMP90_STATE_DIR`.
Сначала установите DKMS и headers текущего ядра:

```bash
# CachyOS
sudo pacman -S --needed dkms linux-cachyos-lts-headers

# Debian 13
sudo apt install dkms "linux-headers-$(uname -r)"
```

Не запускайте миграцию во время Gen2-прохода. Затем:

```bash
sudo ./unlock_cmp90hx.sh install-dkms
dkms status -m cmp90hx-nvidia -v 610.43.03-gen2.1
modinfo -n nvidia
modinfo -p nvidia | grep cmp90_gen2_idx
```

Команда не устанавливает userspace, CUDA или демон заново, не запускает
consume/hammer и не выгружает работающие модули. Сборка/копирование файлов
меняет модули на диске. После успешной миграции обновляются обе runtime-копии
для работы с путём модуля из `modinfo` и сжатым `.ko`; выбор fast/full сохраняется.
`nvidia-pstated` продолжает работать с прежней службой.

Перед первой проверкой выполните холодное выключение с отсутствием питания
карты >=60 секунд, затем проверьте:

```bash
sudo ./unlock_cmp90hx.sh verify
systemctl status cmp90hx-gen2-fast.service nvidia-pstated-cmp90hx.service
journalctl -b -u cmp90hx-gen2-fast.service --no-pager
```

Ожидаются версия NVIDIA 610.43.03, успешный compute, Gen2 5.0 GT/s,
`FAST_SUCCESS` либо успешный полный fallback и работоспособная вычислительная
нагрузка. Пересборка сама по себе не доказывает, что GPU успешно разблокирован.

## Новая установка

После установки зависимостей из README и DKMS:

```bash
sudo ./unlock_cmp90hx.sh install --dkms
```

Обычный `install` без флага остаётся ручным путём до первой регистрации DKMS.
При уже зарегистрированном `cmp90hx-nvidia` повторный `install` сохраняет
DKMS-режим, чтобы не перезаписать его ручными модулями.

## Что делает DKMS

Исходники NVIDIA Open скачиваются/распаковываются при подготовке: архив
610.43.03 около 26 МиБ, не CUDA runfile размером в несколько ГБ. Используется
сохранённый архив `driver/.build`, если он уже есть. В распакованных исходниках
применяются те же патчи и source-адаптации выбранного сборщика Rhonstin.
Его системный установочный хвост не запускается.

Подготовленные исходники копируются в
`/usr/src/cmp90hx-nvidia-610.43.03-gen2.1`; DKMS ведёт рабочие сборки в
`/var/lib/dkms/cmp90hx-nvidia/`. Не удаляйте `/usr/src`-копию: она нужна для
следующих обновлений. Дополнительные распакованные и рабочие копии занимают
существенно больше места, чем архив.

Пересборка выполняется без сети под **переданное DKMS целевое ядро**,
не обязательно загруженное. Компилятор выбирается по config этого ядра;
headers и соответствующий GCC/Clang должны быть установлены. Собираются
`nvidia` и `nvidia-uvm`, как в прежнем compute/headless пути. DRM/modeset/peermem
не добавляются.

Сборщик проверяет vermagic обоих модулей, наличие `GEN2CHAIN` и отсутствие
исполняемого старого `REJOIN16`. DKMS подписывает/сжимает и устанавливает
модули по правилам дистрибутива. На Debian путь может быть `updates/dkms`,
а не `updates/cmpunlocker-90hx-stockflow`. Наш runtime выбирает путь через
`modinfo` и проверяет параметр `cmp90_gen2_idx`, поэтому stock-модуль
не принимается за патченный только по имени.

Ручной каталог `updates/cmpunlocker-90hx-stockflow` текущего ядра переносится
в `cmp90hx-work/backups/*-pre-dkms-*` только после успешной сборки, перед
DKMS install. Прежние compute-only модули также сохраняются. Работающий
модуль остаётся в памяти. Другой зарегистрированный NVIDIA DKMS-пакет
считается конфликтом; автоматически он не удаляется.

## Обновление ядра

Обновляйте ядро вместе с соответствующими headers. После транзакции,
**до перезагрузки**, проверьте конкретный новый release (пример замените
реальным именем из `/lib/modules`):

```bash
dkms status
modinfo -k <new-kernel-release> -n nvidia
modinfo -k <new-kernel-release> -p nvidia | grep cmp90_gen2_idx
```

Для нового ядра запись должна быть `installed`. Если нужно вручную
дозапустить сборку уже установленных ядра и headers:

```bash
sudo dkms autoinstall -k <new-kernel-release>
```

Установка DKMS использует стандартные kernel/package hooks. На CachyOS
ALPM DKMS hook должен выполняться до mkinitcpio hook; при миграции скрипт
явно вызывает `mkinitcpio -P`. На Debian post-install обновляет существующий
initramfs целевого ядра; новый image создаётся штатными kernel hooks.

Если сборка упала или выбран stock-модуль, оставайтесь на старом рабочем
ядре. Ищите `make.log` под `/var/lib/dkms/cmp90hx-nvidia/`. Установка
`nvidia-utils` другой версии по-прежнему может нарушить userspace/kernel
соответствие: DKMS решает пересборку ядра, но не обновление NVIDIA-стека.

## Возврат к ручной установке

Сохраните рабочий каталог и резервные модули. Чтобы прекратить автоматические
пересборки и вернуться на прежний установщик, сначала удалите регистрацию
и модули DKMS:

```bash
sudo dkms remove -m cmp90hx-nvidia -v 610.43.03-gen2.1 --all
```

Это удаляет установленные DKMS-копии с диска, не выгружая модуль из памяти.
До перезагрузки выполните обычный `install` скриптом из `master`, чтобы
восстановить ручную сборку, затем холодное выключение и `verify`.
Один `enable-full` не отключает DKMS: он переключает только Gen2-алгоритм.
Каталог `/usr/src` после удаления регистрации может остаться. Повторная
миграция не перезаписывает такой незарегистрированный каталог; проверенную
копию можно снова зарегистрировать через `dkms add`.

## Локальная проверка разработки

```bash
bash -n unlock_cmp90hx.sh
python3 -m unittest test_dkms -v
```

Расширенные offline-тесты используют заранее скачанные публичные исходники:

```bash
CMP90_TEST_UPSTREAM=/path/to/pinned-rhonstin \
CMP90_TEST_NVIDIA_ARCHIVE=/path/to/open-gpu-kernel-modules-610.43.03.tar.gz \
  python3 -m unittest test_dkms -v
```

Они проверяют применение настоящих патчей, границы подготовки/установки,
передачу headers будущего ядра во все make-проходы, отказ при чужом vermagic,
DKMS-конфигурацию и выбор сжатого патченного модуля вместо stock.
Компиляция под целевые 6.12/6.18 и аппаратная миграция на testrig ещё требуют
проверки; сами тесты не регистрируют системный DKMS и не меняют драйвер.
